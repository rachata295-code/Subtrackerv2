## 1. ทำไม (คำพูดเจ้าของ)

1. "อยากเห็นกราฟว่าแต่ละเดือนใช้เงินไปกับอะไรบ้าง"
2. "บางครั้งอยากเมมของวันนั้นทีเดียว แต่ต้องปัดจอไปหน้าอื่นเพื่อคิดเลขรวมกัน" + "อยากให้มีรายการล่าสุดให้กดเป็น hot bar เพราะของในมอราคาใกล้ๆ กันหมด"
3. "ชอบวางแผนการเงินล่วงหน้า ต้องจ่ายเท่านั้น เก็บเท่านั้น แล้วเอาเงินปัจจุบัน + เงินที่กำลังจะได้ หักลิสต์ที่หักไว้ล่วงหน้า เพื่อให้สบายใจว่าไม่ได้พลาดตรงไหน ถ้ายอดในแอปไม่ตรงกับในบัญชี" · ยอดไม่ตรงส่วนใหญ่เพราะ **ลืมจดรายการ**

**ความสำเร็จ:** เปิดแอปแล้วตอบได้ใน 10 วินาทีว่า (ก) รอบนี้เงินหมดไปกับอะไร (ข) ใช้ได้อีกเท่าไหร่จริงๆ หลังหักของที่ต้องจ่าย/เก็บ (ค) ยอดในแอปตรงกับธนาคารไหม ถ้าไม่ตรง ลืมจดอะไร — และจดของทั้งวันได้โดยไม่ต้องออกไปแอปเครื่องคิดเลข

**ไม่ใช่เป้าหมาย:** แจ้งเตือน push · นำเข้า statement · ดึงยอดจากธนาคารอัตโนมัติ · หลายผู้ใช้ · backup ไฟล์ (เลื่อนไปเฟส 3)
**Anti-goal:** ทำให้การจดรายจ่ายช้าลง · ตัวเลขสองหน้าบอกไม่ตรงกัน (ภาพรวม vs แผน vs เช็กยอด ต้องใช้ฟังก์ชันเดียวกัน) · ยอดบัญชีที่แอปคำนวณ "เพี้ยนสะสม" จนไม่มีใครเชื่อ

## 2. ทางที่พิจารณา (ข้อ 3) — เจ้าของเลือก **ก**

| ทาง | คืออะไร | ได้ | เสีย |
|---|---|---|---|
| **ก. แอปนับยอดบัญชีเอง + จุดเช็กยอด** ✅ | ตั้งยอดเริ่มต้นครั้งเดียว แอปคำนวณ "ยอดที่ควรเหลือ" จากรายการ · เจ้าของพิมพ์ยอดจริงเป็นครั้งคราว → เห็นส่วนต่าง → จดที่ลืม/บันทึกส่วนต่าง → กลายเป็นจุดอ้างอิงใหม่ | จับ "ลืมจด" ได้ · เห็นว่าพลาดช่วงไหน · หมวด "ลืมจด" ขึ้นกราฟ | ต้องจดเงินเข้า (นอกจากเงินเดือน) ด้วย |
| ข. หน้าคิดเลขอย่างเดียว | พิมพ์ยอดปัจจุบัน + เงินเข้า − รายการกันไว้ | ง่าย | แอปไม่รู้ว่ายอดควรเป็นเท่าไหร่ → จับลืมจดไม่ได้ (ปัญหาหลัก) |

ข้อ 1 และ 2 มีทางเดียวที่สมเหตุสมผล (ด้านล่าง)

## 3. ฟีเจอร์ A — สรุปการใช้เงิน (กราฟ)

- **ที่อยู่:** หน้า `/entries` เพิ่ม SegmentedControl บนสุด `รายการ | สรุป` **[call]** (ไม่เพิ่มแท็บ — สรุปคือมุมมองของรายการเดียวกัน)
- **หน่วยเวลา:** รอบเงินเดือน 10→10 (`payPeriod`) ไม่ใช่เดือนปฏิทิน **[call]**
- **นับอะไร (การ "ใช้" ไม่ใช่การ "จ่ายบิล"):**
  - transaction `out` → หมวดของมัน (รอบ = `payPeriod(date)`)
  - subscription charge → หมวด `subscription` (รอบ = `payPeriod(chargeDate)`)
  - installment charge → หมวด `installment` (รอบ = `payPeriod(chargeDate)`)
  - **ไม่นับ** `BillPayment` (จะนับซ้ำกับ charge ที่อยู่ในบิล) · **ไม่นับ** หมวด `savings` เป็นการใช้ (แสดงแยกเป็น "เก็บ")
  - หมวด `unknown` (out) **นับ** เป็นการใช้ แสดงเป็นแท่ง "ลืมจด" สีเทา · transaction `in` ไม่หักลบหมวดใด (ไม่มีการคืนเงินในเฟสนี้)
- **มุมมอง:**
  1. หัว: ยอดใช้รวมรอบที่เลือก + เทียบรอบก่อน (`+฿420 จากรอบก่อน`)
  2. แท่งแนวนอนเรียงหมวดมาก→น้อย (ยอด + %) — กดหมวด → ไปแท็บ `รายการ` พร้อมตัวกรองหมวดนั้น
  3. กราฟแท่งซ้อน 6 รอบล่าสุด (แกน x = รอบ, สี = หมวด) · กดแท่ง = เลือกรอบ
  4. บรรทัด "เก็บรอบนี้ ฿X" และ "ลืมจด ฿Y" (ถ้ามี)
- **สีหมวด:** ใช้ hue ที่มีอยู่ 6 สี + `stone` เป็น "อื่นๆ" — หมวดที่เกิน 6 รวมเป็น "อื่นๆ" ในกราฟซ้อน (รายการแท่งแนวนอนยังแยกครบ) **[call]**
- **เทคนิค:** SVG วาดเอง ไม่เพิ่ม library กราฟ **[call]** (bundle ใหญ่อยู่แล้ว 662 KB · กราฟแค่ 2 แบบ) · ทำตาม skill `dataviz` · มี `<table>` ซ่อนให้ screen reader
- **Desktop:** แท่งแนวนอนซ้าย + กราฟ 6 รอบขวา · mobile เรียงลง

## 4. ฟีเจอร์ B — จดเร็ว

### B1. ช่องเงินคิดเลขได้
- `CurrencyField` รับนิพจน์ `+` `−`(หรือ `-`) ระหว่างตัวเลข เช่น `45+60+35`, `120-15`, `1,200+45.50` · แสดงผล "= ฿140.00" ใต้ช่องทันทีที่พิมพ์ · ค่าที่บันทึก = ผลลัพธ์ (satang)
- ไม่รับ `×` `÷` วงเล็บ **[call]** (YAGNI) · ผลติดลบหรือ 0 → error "ยอดต้องมากกว่า 0" · นิพจน์ไม่สมบูรณ์ (`45+`) → ยังไม่ valid, ไม่ crash
- ใช้ `parseAmount` เดิมกับแต่ละตัวเลข (กติกาคอมม่าเดิม)
- บนมือถือ: `inputMode="decimal"` ไม่มีปุ่ม + บน iOS → แสดงแถบปุ่มเล็ก `+` `−` เหนือคีย์บอร์ดในฟอร์ม **[call]**

### B2. จดหลายรายการทีเดียว
- `QuickAddSheet` เพิ่มปุ่ม "+ เพิ่มอีกรายการ" → แถวใหม่ (ชื่อ/โน้ต, ยอด, หมวด) ใช้วันที่ ช่องทาง ก้อนเงินร่วมกันจากหัวฟอร์ม (แก้ต่อแถวได้ผ่าน "ตัวเลือกเพิ่ม") · ปุ่มบันทึก "บันทึก 3 รายการ · ฿265" · บันทึกทีเดียว (`createTransactions` batch)
- ล้มเหลวบางแถว → ไม่บันทึกเลย (atomic) + toast error **[call]**

### B3. แถบทางลัด (hot bar)
- แถวปุ่มเลื่อนแนวนอน บนหัว `QuickAddSheet` และในหน้าภาพรวมใต้ปุ่มเพิ่ม **[call]**
- ที่มา: transaction `out` 60 วันล่าสุด จัดกลุ่มตาม (`note` ตัดช่องว่าง/ตัวพิมพ์, `amount`, `category`, `sourceId`, `potId`) → เรียงตามจำนวนครั้ง แล้วล่าสุด → 8 อันแรก · ต้องเคยซื้อ ≥ 2 ครั้ง
- ปุ่มแสดง "ข้าวมันไก่ ฿45" · **กดครั้งเดียว = บันทึกวันนี้ทันที** + toast "บันทึกข้าวมันไก่ ฿45 · เลิกทำ" (5 วิ) · กดค้าง/คลิกขวา = เปิดฟอร์มเติมค่าให้แก้ก่อน
- ปักหมุด/ซ่อนรายการ: ไม่ทำในเฟสนี้ **[call]**
- คำนวณใน domain (`hotbarItems(data, today)`) ไม่มีตารางใหม่

## 5. ฟีเจอร์ C — วางแผน & เช็กยอดบัญชี (ทาง ก)

### C1. แท็บใหม่ `/plan` "แผน"
- เมนูเป็น 5 ข้อ: ภาพรวม · รายการ · **แผน** · บิล & ผ่อน · ตั้งค่า (ที่ 375px ข้อละ 75px ยังพอ — ตรวจไม่ล้น)

### C2. ยอดบัญชีที่ "ควรเหลือ"
- ใช้กับช่องทาง `kind = 'bank'` เท่านั้น (บัตร/SPayLater ไม่มี "ยอดคงเหลือ" ในความหมายนี้)
- **จุดอ้างอิง (`BalanceCheck`)**: ยอดจริงที่เจ้าของพิมพ์ ณ วันหนึ่ง · จุดแรก = "ยอดเริ่มต้น" ตอนตั้งค่า
- `expectedBalance(sourceId, data)` (ยอด ณ ตอนนี้) = `actual` ของจุดอ้างอิงล่าสุด (เรียง `checkedOn`, แล้ว `createdAt`)
  \+ Σ transaction `in` ของบัญชีนี้ที่ "อยู่หลังจุดอ้างอิง"
  − Σ transaction `out` ของบัญชีนี้ที่ "อยู่หลังจุดอ้างอิง"
  − Σ `BillPayment` ที่ "อยู่หลังจุดอ้างอิง" และบิลนั้นจ่ายจากบัญชีนี้ (`source.payFromSourceId`)
- **"อยู่หลังจุดอ้างอิง"** = `date > checkedOn` **หรือ** (`date = checkedOn` **และ** `createdAt > check.createdAt`) — เพราะเช็กตอนเช้าแล้วซื้อของตอนบ่ายวันเดียวกันต้องถูกนับ · ต้องใช้คอลัมน์ `transactions.created_at` และ `bill_payments.created_at` (ถ้ายังไม่มีใน schema ให้เพิ่ม default `now()`) **[call]**
- **จดย้อนหลังก่อนจุดเช็ก** (`date < checkedOn` หลังเช็กไปแล้ว): ไม่กระทบยอดบัญชี (ยอดจริงรวมไว้แล้ว) — ฟอร์มแสดงคำเตือนเล็ก "รายการนี้อยู่ก่อนเช็กยอดล่าสุด จึงไม่เปลี่ยนยอดบัญชี" แต่ยังบันทึกได้ (ไปอยู่ในกราฟ) **[call]**
- **ระหว่างเช็กยอด (C3)** จุดอ้างอิงใหม่ยังไม่ถูกสร้าง → รายการที่จดเพิ่มใน sheet ทุกวันที่ (≥ จุดเช็กก่อนหน้า) เปลี่ยนส่วนต่างสดได้จริง
- **transaction ส่วนต่าง (`unknown`)** ลงวันที่ = `checkedOn` และสร้าง **ก่อน** แถว `BalanceCheck` (createdAt น้อยกว่า) → ไม่ถูกนับซ้ำหลังจุดอ้างอิงใหม่
- **ไม่มีเงินอัตโนมัติ** — เงินเข้าทุกบาทต้องเป็น transaction `in` (ดู C7) จึงไม่มีทางนับเงินเดือนซ้ำ
- `expectedBefore` เก็บเป็น snapshot ตอนเช็ก (แก้รายการเก่าทีหลัง ประวัติไม่คำนวณใหม่) **[call]**
- ข้อจำกัดที่ต้องบอกในหน้าจอ: ยอด "ควรเหลือ" ถูกต้องเท่าที่จดเงินเข้า-ออกครบ — ซึ่งคือจุดประสงค์ของการเช็ก
- **บัญชีที่ยังไม่มีจุดอ้างอิง:** การ์ดแสดง "ตั้งยอดเริ่มต้น" แทนตัวเลข · ยอดเริ่มต้นลงวันที่วันนี้เท่านั้น (ย้อนหลังไม่ได้) **[call]**
- **ขอบเขต:** ทุกตัวเลขแยกต่อบัญชีธนาคาร · ถ้ามีบัญชีธนาคารมากกว่า 1 หน้าแผนมีตัวเลือกบัญชี (ค่าเริ่มต้น = บัญชีที่รับเงินเข้ามากสุดจาก C7) · ไม่มีการโอนระหว่างบัญชีในเฟสนี้ (จดเป็น out ฝั่งหนึ่ง + in อีกฝั่ง) **[call]**

### C3. ขั้นตอนเช็กยอด (หัวใจของฟีเจอร์)
1. หน้าแผน → การ์ดบัญชี "ในแอปควรเหลือ ฿4,320.50 · เช็กล่าสุด 3 วันก่อน" → ปุ่ม **"เช็กกับยอดจริง"**
2. Sheet: พิมพ์ยอดจากแอปธนาคาร (ช่องคิดเลขได้ B1) → แสดงทันที:
   - ตรง (ต่าง < ฿1) → "ตรงกัน 👍" → บันทึกเป็นจุดอ้างอิง
   - ยอดจริง **น้อยกว่า** → "หายไป ฿130 — ลืมจดอะไรไหม?" + **hot bar** (B3) + รายการ 5 อันล่าสุดของบัญชีนี้ไว้เทียบ · กดของที่ลืม → จดเป็นวันนี้ (แก้วันได้) → ส่วนต่างอัปเดตสด
   - ยอดจริง **มากกว่า** → "เกินมา ฿200 — มีเงินเข้าที่ยังไม่ได้จดไหม?" + ปุ่ม "จดเงินเข้า"
3. ยังเหลือส่วนต่าง → เลือก **"บันทึกส่วนต่างเป็น ลืมจด"** (สร้าง transaction หมวด `unknown` direction ตามทิศ) หรือ **"แค่บันทึกยอด"** (ไม่สร้าง transaction — ส่วนต่างไปอยู่ในจุดอ้างอิง)
4. บันทึก → สร้าง `BalanceCheck { actual, expectedBefore }` → จุดอ้างอิงใหม่ · toast
- ประวัติเช็กยอด: รายการเล็กใต้การ์ด "15 พ.ย. ต่าง −฿130 (ลืมจด)" — เห็นว่าพลาดช่วงไหน

### C4. แผนรอบนี้
- รายการแผนต่อรอบ (`PlanItem`): ชื่อ · ยอด · ชนิด `pay` (ต้องจ่าย) / `save` (เก็บ) · บัญชีที่ออก · วันที่ (ไม่บังคับ) · สถานะ ทำแล้ว/ยัง
- **เติมให้อัตโนมัติ (อ่านอย่างเดียว ไม่ต้องสร้าง PlanItem):** บิลบัตร/SPayLater ที่ครบกำหนดในรอบนี้และยังไม่จ่าย (จาก `upcomingOutflows`, `counted:true`) — แสดงในลิสต์เดียวกัน ป้าย "บิล" · กด = ไปจ่ายที่หน้าบิล
- PlanItem `save` กด "เก็บแล้ว" → สร้าง transaction `out` หมวด `savings` จากบัญชีนั้น · `pay` กด "จ่ายแล้ว" → สร้าง transaction `out` หมวดที่เลือก (default `bills`) — เพื่อให้ยอดบัญชีลดจริง
- **คัดลอกจากรอบก่อน:** ปุ่ม "ใช้แผนรอบก่อน" คัดลอก PlanItem ทั้งหมด (สถานะ = ยัง) **[call]** — เพราะของต้องจ่าย/เก็บส่วนใหญ่ซ้ำทุกเดือน

### C5. "ใช้ได้จริง" (ตัวเลขที่ทำให้สบายใจ) — เจ้าของเลือก **หักเงินที่เหลือในก้อนด้วย**
```
เงินในบัญชีตอนนี้ (ควรเหลือ)                       ฿4,320.50
+ เงินประจำที่จะเข้า (C7 · แม่ 10 ธ.ค.)               ฿X
− บิลที่ยังไม่จ่าย (จ่ายจากบัญชีนี้)                   ฿2,458.93
− แผนที่ยังไม่ทำ (ต้องจ่าย ฿1,500 · เก็บ ฿2,000)       ฿3,500.00
− ที่เหลือในก้อน (ใช้จ่ายจำเป็น ฿5,100 · ใช้ตามใจ ฿662) ฿5,762.07
= ใช้ได้จริง (เงินที่ยังไม่ได้จัดให้อะไรเลย)              ฿…
```
- **ความหมาย:** เงินที่ยังไม่มีหน้าที่ · ติดลบ = "แผนเกินเงินที่มี ฿…" (สีเตือน) — ไม่ใช่ "ใช้เล่นได้"
- **ก้อนที่หัก:** `potStatus(pot, currentPeriod).left` ที่ > 0 ของทุกก้อน (ก้อนที่ติดลบไม่บวกคืน) · หัก **เฉพาะรอบปัจจุบัน** **[call]**
- **กันนับซ้ำกับก้อน:** `potStatus.left` หักบิลที่นับในก้อน (`reserved`) ไปแล้ว → บรรทัด "บิลที่ยังไม่จ่าย" นับ **เฉพาะบิลที่ไม่ได้อยู่ในก้อน** (charge ที่ `potId = null`, เช่นผ่อนที่ตั้ง "แยก") · domain ต้องมี test ที่พิสูจน์ว่าบิล 1,077 ไม่ถูกหักสองครั้ง
- **ช่วงเวลา:** วันนี้ (รวม) → สิ้นรอบเงินเดือนปัจจุบัน **[call]** (เปลี่ยนจากร่างแรก: เพราะหักก้อนรายรอบ ถ้ายืดไปรอบหน้าต้องหักก้อนรอบหน้าด้วยและตัวเลขจะเยอะเกินอ่าน) · เงินประจำที่จะเข้าในช่วงนี้ = เฉพาะรายการ C7 ที่ยังไม่ได้กดรับ
- **ไม่รวมรายได้ไม่แน่นอน** (พาร์ทไทม์, Fastwork) ในการคาดการณ์ — นับเมื่อเข้าจริงเท่านั้น **[call]** (สบายใจ = ประมาณต่ำไว้ก่อน)
- **บิลในช่วง:** ใช้ `billAmount` ของรอบบิลนั้น (รวม charge subscription/ผ่อนที่รู้ล่วงหน้า) · ไม่คาดการณ์ยอดรูดบัตรในอนาคต
- **แผนที่นับ:** PlanItem ของรอบปัจจุบันที่ยังไม่ทำ · PlanItem ต้องใช้บัญชีธนาคารเท่านั้น (บัตรเลือกไม่ได้) · ไม่ต้องมี PlanItem สำหรับบิลบัตร/SPayLater (เติมให้อัตโนมัติแล้ว C4) — ฟอร์มเตือนถ้าชื่อซ้ำกับบิล
- ใต้ตัวเลข: **ไทม์ไลน์** (เงินเข้า/บิล/แผนที่มีวันที่) พร้อมยอดคงเหลือสะสม · วันเดียวกัน **เงินออกก่อนเงินเข้า** (มองแย่สุดไว้ก่อน) **[call]** · ไฮไลต์ **"จุดต่ำสุด ฿… วันที่ …"** (ติดลบ = "เงินไม่พอวันที่ …") · ก้อนเงินไม่อยู่ในไทม์ไลน์ (ไม่มีวันที่) แสดงเป็นบรรทัดสรุปท้าย
- คำนวณใน domain `forecast(data, sourceId, today)` ฟังก์ชันเดียว — ภาพรวมใช้ตัวเลขเดียวกัน

### C7. เงินเข้า (แทน "เงินเดือนอัตโนมัติ")
เจ้าของมีเงินเข้า 2 แบบ:
- **เงินประจำ (ยอดคงที่):** เงินจากแม่ วันที่ 10 และวันที่ 24 (ยอดตั้งได้ในตั้งค่า) — โมเดล `RecurringIncome`
  - วันที่ถึง (และหลังจากนั้นจนกว่าจะกด) หน้าภาพรวมขึ้นการ์ด **"เงินจากแม่เข้าแล้ว? ฿X"** → กดครั้งเดียว = transaction `in` หมวด `allowance` วันนี้ (แก้ยอด/วันได้) ผูก `recurringIncomeId` + `incomeDueOn` · กด "ยังไม่เข้า" = ซ่อนถึงพรุ่งนี้
  - เพราะเงินมักไม่เข้าตรงวัน — ยอดบัญชีจึงตรงกับวันที่เงินเข้าจริง และไม่มีทางนับซ้ำ
- **รายได้ไม่แน่นอน:** พาร์ทไทม์ (ได้หลังเสาร์-อาทิตย์), Fastwork (อนาคต), อื่นๆ → จดเองผ่าน QuickAdd สลับเป็น "เงินเข้า" · หมวด `parttime` / `freelance` / `other`
- `settings.salary` เดิม (10,200) ยังใช้เป็นตัวเลขอ้างอิงของก้อน — ไม่ใช้ในยอดบัญชี

### C6. ภาพรวม
- การ์ด "เงินเข้าแล้ว?" (C7) อยู่บนสุดเมื่อมี
- การ์ดเล็ก "ใช้ได้จริง ฿… · เช็กยอดล่าสุด 3 วันก่อน" → กดไป `/plan` · ถ้าไม่เคยเช็ก > 7 วัน → ป้าย "ถึงเวลาเช็กยอดแล้ว" **[call]**

## 6. โมเดลข้อมูล (เพิ่ม)

```ts
type Category = 'food'|'transport'|'shopping'|'entertainment'|'health'|'bills'|'other'
              | 'savings'    // เก็บเงิน (out · ไม่นับเป็นการใช้ในสรุป)
              | 'unknown'    // ลืมจด / ส่วนต่างจากเช็กยอด (out หรือ in)
              | 'allowance'  // เงินประจำ (in)
              | 'parttime'   // พาร์ทไทม์ (in)
              | 'freelance'; // Fastwork ฯลฯ (in)
// ฟอร์มแสดงหมวดตามทิศ: out = food…other, savings, unknown · in = allowance, parttime, freelance, other, unknown
// ในสรุปเท่านั้น (ไม่เก็บใน DB): 'subscription' | 'installment'

interface Transaction { /* เดิม */ createdAt: string; recurringIncomeId: string | null; incomeDueOn: ISODate | null; }
interface BillPayment { /* เดิม */ createdAt: string; }

interface RecurringIncome {
  id: string; name: string;  // 'เงินจากแม่'
  amount: Satang; dayOfMonth: number; // 10, 24 (เกินวันในเดือน → วันสุดท้าย)
  sourceId: string;          // บัญชีที่รับ (bank)
  active: boolean;
}

interface BalanceCheck {
  id: string; sourceId: string; checkedOn: ISODate;
  actual: Satang;            // ยอดจริงที่พิมพ์
  expectedBefore: Satang | null; // ยอดที่แอปคำนวณก่อนเช็ก (null = จุดเริ่มต้น)
  adjustmentTxId: string | null; // transaction 'unknown' ที่สร้างจากส่วนต่าง (ถ้ามี)
  createdAt: string;         // timestamp — หลายครั้งในวันเดียว ใช้อันล่าสุด
}

interface PlanItem {
  id: string; periodKey: PeriodKey; name: string; amount: Satang;
  kind: 'pay'|'save'; sourceId: string; dueOn: ISODate | null;
  category: Category;        // ใช้ตอนสร้าง transaction เมื่อกดทำแล้ว (save → 'savings')
  doneTxId: string | null;   // transaction ที่สร้างตอนกดทำแล้ว · null = ยังไม่ทำ · กดยกเลิก = ลบ tx นั้น
  sortOrder: number;
}
```
- `FinanceData` เพิ่ม `balanceChecks`, `planItems`, `recurringIncomes`
- SQL: migration ใหม่ `supabase/migrations/2026-11-16-phase2.sql` (idempotent) + อัปเดต `schema.sql` · ขยาย check constraint ของ `category` · ตาราง `balance_checks`, `plan_items`, `recurring_incomes` RLS `user_id = auth.uid()` · `transactions.created_at`/`recurring_income_id`/`income_due_on`, `bill_payments.created_at` (ถ้ายังไม่มี, default `now()`) · seed: ไม่สร้าง RecurringIncome ให้ (เจ้าของตั้งเองในตั้งค่า)
- **Pot:** transaction หมวด `savings`, `unknown` และที่สร้างจาก PlanItem มี `potId = null` เสมอ → ไม่กระทบ `potStatus` เดิม · transaction `in` ไม่นับใน pot (เหมือนเดิม)
- Domain ใหม่ (pure, test ด้วยตัวเลขจริง): `spendingByCategory(data, periodKey)`, `spendingHistory(data, periodKey, n)`, `hotbarItems(data, today, limit=8)`, `evaluateAmountExpression(text): {value: Satang} | {error}`, `expectedBalance(sourceId, data)`, `pendingIncomes(data, today)` (การ์ด C7), `forecast(data, sourceId, today): {start, incoming, bills, plans, potsLeft, available, timeline, low}`
