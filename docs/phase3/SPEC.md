สถานะ: DRAFT รออนุมัติ (2026-11-16) · มาจากการใช้จริงของเจ้าของแอป (มีภาพหน้าจอ iPhone 5G)
ตัดออก: นำเข้าข้อมูลจาก v1 (เจ้าของตอบ "ไม่ต้อง เดี๋ยวกรอกเอง")

## A. บั๊กฟอร์ม (BottomSheet) บนมือถือ — ความสำคัญสูงสุด

อาการ (จากเจ้าของ):
1. เปิดฟอร์มจดรายการ พิมพ์ค้างไว้ แล้ว "เลื่อนขึ้นเพื่อแก้ไข" → ฟอร์มปิด/หายทั้งหมด ต้องพิมพ์ใหม่
2. บางครั้งคีย์บอร์ดขึ้นแล้ว sheet ถูกตัด: เห็นแค่ช่องจำนวนเงิน + โน้ต + แถวหมวดที่โดนตัดครึ่ง มีที่ว่างเปล่ากว้างระหว่างเนื้อหากับคีย์บอร์ด (ภาพหน้าจอ)

สาเหตุที่ตรวจเจอในโค้ด:
- ฟอร์มเก็บ state ใน `QuickAddForm` / `EntryForm` ซึ่งถูก unmount ทุกครั้งที่ `open=false` (`{open ? <Form key=…/> : null}`) → Vaul ตีความการลากแนวตั้งในเนื้อหา/การเปลี่ยน viewport ของ iOS เป็นการปิด sheet → state หายหมด
- `BottomSheet` ใช้ `max-h-[90dvh]` + Vaul `repositionInputs` (default) → ตอนคีย์บอร์ดขึ้น `dvh` บน iOS Safari ไม่หด แต่ visualViewport หด ทำให้ความสูง/ตำแหน่ง sheet เพี้ยน เห็นเป็นช่องว่าง + เนื้อหาโดนตัด

สัญญา (ต้องทำครบ):
- **A1 ไม่เสียงานที่พิมพ์** — ฟอร์มสร้างใหม่ (QuickAddSheet, EntrySheet โหมดเพิ่ม, และ sheet อื่นที่ผู้ใช้พิมพ์: Subscription/Installment/PlanItem/RecurringIncome/BalanceCheck) เก็บ draft ไว้ในหน่วยความจำของ session (module-level store หรือ context เหนือ `open`) แล้วเติมกลับเมื่อเปิดใหม่ · ล้าง draft เมื่อ **บันทึกสำเร็จ** หรือกด "ล้าง/ยกเลิก" ชัดเจน · ปิดด้วยการลาก/แตะนอก sheet = **ไม่ล้าง** draft · โหมดแก้ไข (editing) ไม่ใช้ draft (เติมจากรายการจริงเหมือนเดิม) · draft เก็บใน memory เท่านั้น ห้ามลง localStorage (ไม่เก็บข้อมูลการเงินในเครื่อง)
- **A2 ลากไม่ปิดโดยบังเอิญ** — บนมือถือให้ Vaul ลากได้เฉพาะแถบ handle/หัว sheet (`handleOnly`) เนื้อหาเลื่อนได้อิสระ · ถ้ามี input โฟกัสอยู่ (คีย์บอร์ดเปิด) การลากลงต้องไม่ปิด sheet
- **A3 เลย์เอาต์ตอนคีย์บอร์ดขึ้น** — คำนวณความสูงสูงสุดจาก `window.visualViewport.height` (ตั้ง CSS variable เช่น `--vvh` ใน hook `useVisualViewportHeight`) แทน `90dvh` · sheet ยึดขอบล่างของ visual viewport · เนื้อหา scroll ได้ครบ · input ที่โฟกัสต้องเห็นเต็ม (scrollIntoView block 'center' หลัง viewport resize) · ไม่มีช่องว่างเปล่าระหว่างเนื้อหากับคีย์บอร์ด · desktop (panel ขวา) ไม่เปลี่ยน
- **A4 ปุ่มบันทึกต้องกดได้เสมอ** — ปุ่มบันทึกอยู่ในพื้นที่ที่เลื่อนถึงได้ตอนคีย์บอร์ดเปิด (ใช้ sticky footer ถ้าจำเป็น)

## B. ปัดซ้ายเพื่อลบ

- component ใหม่ `SwipeToDelete` (`src/components/ui/SwipeToDelete.tsx`) ห่อ `ListRow`: ปัดซ้ายเผยปุ่มแดง "ลบ" (กว้าง ≥ 72px สูงเท่าแถว) · ปัดต่อจนสุด/กดปุ่ม = ลบ · ปัดกลับ/แตะที่อื่น = ปิด · เปิดได้ทีละแถว
- Gesture: pointer events + `touch-action: pan-y` (เลื่อนแนวตั้งของหน้ายังทำงาน) · ติดนิ้ว 1:1 · velocity flick ได้ · rubber-band ขอบ · ล็อกแกนหลังขยับ >8px (แนวตั้งปล่อยให้หน้าเลื่อน) · animation เฉพาะ transform · reduced-motion = ไม่มี transition
- ลบแล้วแสดง toast "ลบ<ชื่อ>แล้ว · เลิกทำ" 5 วิ (เลิกทำ = สร้างกลับด้วยข้อมูลเดิม id ใหม่ได้) แล้วใช้ `AnimatedRow leaving` เดิม
- Accessibility: ปุ่มลบเป็น `<button>` จริง (keyboard/สกรีนรีดเดอร์เข้าถึงได้โดยไม่ต้องปัด) เช่น เมื่อ focus ที่แถวกด Delete / มีปุ่ม "ลบ" ซ่อนตาม focus · desktop (pointer: fine) ไม่ปัด ใช้ปุ่มลบเดิมใน sheet
- ใช้กับ: รายการ (`/entries`), บิล/สมาชิก/ผ่อน (`/bills`), แผนรอบนี้ (`/plan` PlanItem), เงินประจำ + ก้อน + ช่องทาง ในตั้งค่า
- ลบที่ **ผูกข้อมูลอื่น** (ช่องทาง/ก้อนที่มีรายการอ้างอิง) ต้องยังใช้กติกา/ข้อความ error เดิมของ `handleDeleteSource` / `handleDeletePot` (ปัดแล้วลบไม่ได้ → toast อธิบาย ไม่ลบเงียบๆ)
- `HoldToDelete` ใน sheet คงไว้ (ไม่ลบทิ้ง)

## C. ล้างข้อมูลทั้งหมด (ตั้งค่า → โซนอันตราย)

- ปุ่ม "ล้างข้อมูลทั้งหมด" ท้ายหน้าตั้งค่า สีแดง แยกจากส่วนอื่น
- sheet ยืนยัน 2 ชั้น: (1) อธิบายว่าจะลบอะไรกี่รายการ (นับจริงจากข้อมูล) และ **กู้คืนไม่ได้** (2) ต้องพิมพ์คำว่า `ล้างข้อมูล` ให้ตรงปุ่มถึงกดได้ + กดค้าง `HoldToDelete`
- ตัวเลือก: ✓ "ล้างการตั้งค่าด้วย (ช่องทาง ก้อนเงิน เงินประจำ รายได้)" ปิดไว้เป็นค่าเริ่มต้น
  - ปกติ (ค่าเริ่มต้น) ลบ: `transactions`, `bill_payments`, `balance_checks`, `plan_items`, `subscriptions`, `installments`
  - รวมตั้งค่า ลบเพิ่ม: `recurring_incomes`, `pots`, `payment_sources` แล้วเรียก seed เดิมให้สร้างค่าเริ่มต้นใหม่ (ไม่ทิ้งบัญชีให้ว่างจนแอปพัง) · `settings` รีเซ็ตเป็นค่าเริ่มต้น ไม่ลบ row
- ทำผ่านชั้น repo (`financeRepo.clearAllData({ includeSetup })`) ใช้ session ของผู้ใช้ (RLS `user_id = auth.uid()`) **ห้ามใช้ service_role** · ลบตามลำดับที่ไม่ชน foreign key (ลูกก่อนแม่) · ล้มกลางทาง → toast error ไทย + invalidate query ให้ UI ตรงกับข้อมูลจริง
- fixture mode (`VITE_USE_FIXTURES=1`): ล้าง in-memory store
- หลังสำเร็จ: invalidate ทุก query · toast "ล้างข้อมูลแล้ว" · พาไปหน้าภาพรวม

## เกณฑ์ผ่าน
1. พิมพ์ในฟอร์ม → ลากปิด → เปิดใหม่ = ข้อมูลที่พิมพ์ยังอยู่ · บันทึกสำเร็จ = ฟอร์มถัดไปว่าง
2. มือถือ 375×667 จำลองคีย์บอร์ด (visualViewport หด ~300px): ไม่มีช่องว่าง ช่องที่โฟกัสเห็นเต็ม ปุ่มบันทึกเลื่อนถึง
3. ปัดซ้ายลบได้ทุกลิสต์ที่ระบุ + เลิกทำ ได้ + ปุ่มลบเข้าถึงด้วยคีย์บอร์ดได้
4. ล้างข้อมูล: นับถูก ต้องพิมพ์ยืนยัน ลบถูกชุดตามตัวเลือก fixture + repo test
5. tests / test:tz / tsc / check:motion / build ผ่าน · ไม่มี horizontal overflow ที่ 375/768/1280
6. ทดสอบบน iPhone จริง (เจ้าของ): บันทึกผลใน PR
